# dbs-speak-human：说人话

把一段话写成或改成真人在那个场合会随口说出的样子；用户给过本人写的话时，按其口吻改。

## 核心任务

> 用户要发一段话给真人看，或者觉得 Agent 写的话「不像人说的」。让这段话读起来像真人在微信里随手打的：对方读着没负担，愿意回，也不会觉得在被推销、被安排或在跟机器人说话。

说人话不等于随便、不等于加语气词。判断标准只有一个：**真人在这个场合，会不会这样说？**

## 第一步：确认场景

动笔前先弄清四件事。能从上下文判断的直接判断，不追问：

1. **谁说**：本人、助理、团队成员，还是 Agent 自己；
2. **对谁说**：陌生人、顾客、熟人、同事、老板；
3. **在哪说**：私聊、群聊、朋友圈、当面；
4. **对方现在处在什么状态**：主动来问的、还没开口的、在犹豫的、已经决定的。

对方的状态决定分寸。对方只是来问一句，就不能写成像要拉他谈话、替他做决定。

用户提供了本人写过的话（原稿、改稿、聊天记录），以它为准学习口吻：用词、语气词、标点习惯、句子长短。用户改过或明确要求保留的句子，不再改动。

## 第二步：写或改

按 [说人话检查清单](references/checklist.md) 逐项处理。最常见的问题按出现频率排在前面：

1. **书面标点**：聊天里不用分号、冒号引出清单、破折号；多件事用逗号连成一口气，或拆成两句；
2. **清单感**：能说成一句话的，不列 1、2、3；非列不可时前面加「比如」；
3. **预设对方**：不替对方决定他要做什么、他有什么问题（「先聊聊你的情况」「方便你随时问」）；写自己这边的安排，并加条件（「有问题的话这边能及时回你」）；
4. **姿态过满**：「我来帮你看」改「我可以来看看」；不揽活，不打包票；
5. **书面腔提问**：「你最想弄清楚的是哪个？」这类问句一律不用；需要对方回应时，用随口的邀请（「有别的问题直接问我就行～」）；
6. **套话**：「第一时间」「为您提供」「相关疑问」「欢迎咨询」这类客服词换成具体说法；
7. **书面词**：提供→给、疑问→问题、其他→别的、如果……可以……→直接说；
8. **评价词代替内容**：透、通、顺、贴、准、稳、实、落、戳、闭环这类词，只说了「好」「完整」「对上了」，没说具体是什么，例如「讲透」「理顺」「贴着用户」。先问它具体指什么，用原文里的具体对象或动作替换；原文没有这个信息，就删掉这半句或问用户，不编造；不换成「深入」「到位」这类同义评价词。字面意思和固定名词不算，例如透明、顺序、准备。完整词表见检查清单第六节；
9. **多余的表态**：不主动说「不合适我们也会直接告诉你」这类对方没问的保证；
10. **虚构的共识**：不写「一般」「大家都」「很多人以为」，除非真有其事；要表达常见，就说实际经历（「之前经常有人问我」）。

改写只动表达。事实、数字、承诺强度、说话人的立场都不变；原文没有的信息不加。

## 第三步：自检

交付前把每句话默念一遍，问四个问题：

1. 当面说这句话，会不会觉得别扭？
2. 对方读完，是知道怎么回，还是有压力、不知道回什么？
3. 去掉这个词、这个分句，意思少不少？不少就删。
4. 有没有哪个字在替我省掉本该写出来的具体内容？有就按第二步第 8 条改。

## 交付

```markdown
（改好的全文，可直接复制）

改了哪些地方：
- 「原句」→「新句」：一句话说明为什么
```

- 改动说明只列实际改动，按原文顺序，每条一行；
- 用户没改过、本来就自然的句子，原样保留，并在最后一句说明哪些没改；
- 用户只要成品时，只给全文；
- 从零写时，只给可直接发出的全文。

## 这条规则也约束 Agent 自己

本 Skill 被调用过的会话里，Agent 回给用户的话同样按这套标准写：直接说结论，短句，不堆术语，不用「本轮方案」「当前判断」这类公文标题包装几句话就能说完的事。

## 不处理

- 公众号长文、短视频文稿等给观众看的内容：本 Skill 只处理要发给对话对象的话；
- 产品、功能、项目说明文：交给平铺直叙写作类能力；
- AI 写作痕迹的检测报告：本 Skill 直接改，不出检测报告；
- 营销定位、标题封面、内容结构：只负责把话说自然，不改内容策略；
- 事实核查：发现事实存疑时提醒用户，不自行改动事实。
