# 输出格式模板

默认输出写在 `SKILL.md`。以下格式按条件使用；空的小节不写，未知项写「未知」。

## 严格问题质量审计

只有用户要求「严格审计」「打分」「判断问题质量」时使用。

```markdown
# 好问题诊断

## 原问题
{用户原话}

## 当前评分
| 检查项 | 得分 | 说明 |
|---|---:|---|
| 对象 | 0-2 | |
| 目标 | 0-2 | |
| 冲突 | 0-2 | |
| 约束 | 0-2 | |
| 反馈 | 0-2 | |

总分：{x}/10

## 最大缺口
{最影响 Agent 推理的缺口}

## 改写成好问题草案
{问题说明书草案}

## 最小下一步
{一个动作。需要用户补信息时，列 0-3 个会改变判断的问题}
```

## Agent 可解性判断

用户问某个任务能不能由 Agent 自动完成时使用。

```markdown
# Agent 可解性判断

## 结论
{A / B / C / D 档}：{一句话说明}

## 为什么
| 判断项 | 结果 | 说明 |
|---|---|---|
| 边界清楚 | 高 / 中 / 低 | |
| 变量可表达 | 高 / 中 / 低 | |
| 反馈可获得 | 高 / 中 / 低 | |
| 解释可检验 | 高 / 中 / 低 | |
| 行动可执行 | 高 / 中 / 低 | |
| 规律稳定 | 高 / 中 / 低 | |

## 可自动化部分
{Agent 可以直接做什么}

## 需要人类介入的部分
{哪些判断、资源、反馈必须由人提供}

## 最小下一步
{先做什么}
```

## 完整问题说明书

清晰度高，或用户要一份可直接交给 Agent 的说明书时使用。

```markdown
# 问题说明书

## 我要分析的问题
{一句话问题}

## 现象
{具体发生了什么}

## 目标
{解释 / 预测 / 改进 / 决策}

## 核心冲突
{哪里和预期不一致}

## 背景事实
{事实、数据、上下文}

## 约束
{不能改变什么，必须考虑什么}

## 反馈入口
{可以观察什么、收集什么、测试什么}

## 请 Agent 做
1. 生成 2-3 个候选解释。
2. 用 hard to vary、可检验性、行动指向批评每个解释。
3. 选出最值得验证的解释。
4. 给出一个最小验证动作。
```

「请 Agent 做」可以按用户任务改写，但要保留候选解释、批评、选择和最小验证动作的链条。

## 候选解释与批评

清晰度达到 8 分以上，或用户明确要求候选解释时使用。

```markdown
# 候选解释与批评

## 当前问题
{已经钉住的问题}

## 候选解释
1. {解释 A}
2. {解释 B}
3. {解释 C，可选}

## Hard to Vary 对比
| 候选 | 机制 | 排除项 | 可验证信号 | 行动变化 | 评分 |
|---|---|---|---|---|---:|

## 当前最强解释
{最 hard to vary 的解释}

## 仍然不确定的地方
{不能假装确定的部分}

## 最小验证动作
{下一步做什么}
```

## 深度升级

模式 E 专用。完整探针写法见 `references/deepen.md`。

```markdown
# 深度升级

## 原题
{用户原题，一句话}

## 专家差距
1. {动作} → 会替换/新增：{交付物的哪部分}
2. {动作} → 会替换/新增：{哪部分}
3. {动作} → 会替换/新增：{哪部分}

## 回到一手素材
- 降级为线索：{用户给的二手材料}
- 必需一手输入：{具体来源类型}
- 拿不到怎么办：{降级方案 / 标记不可解}

## 方法与工具
- {方法名}：{怎么用它，会改变什么结论}
- {工具/动作}：{具体动作}

## 独立验证锚点
- 验证方：{除提问者和 AI 之外，谁能独立判断}
- 可观测量：{具体查什么}
- 通过标准：{什么结果算对}

## 深度判据
| 判据 | 升级前 | 升级后 |
|---|---|---|
| 一手证据层数 | {n} | {n} |
| 可证伪性 | {有无具体观察} | {有无} |
| 推理链长度 | {直接检索 / A→B→C} | {直接检索 / A→B→C} |
| 交付物数量 | {n} | {n}（不变） |

## 升级后的题目
{一段可直接交给 Agent 的题目}

## 仍然不确定的地方
{缺什么、风险在哪}
```
