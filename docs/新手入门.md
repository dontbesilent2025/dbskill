# dbskill 新手入门

你可能是看到有人用 dbskill 推进真实任务，想知道自己该怎么开始。

dbskill 由自媒体博主 dontbesilent 创建，全网可搜 `@dontbesilent 聊赚钱`。dontbesilent 累计发布 16152 条推文，dbskill 将其中经过筛选的内容整理为 4176 个知识原子和 34 个当前业务 Skill，用来处理问题、材料、目标、选择和持续卡点；另保留 2 个 deprecated 旧入口。

你不需要记住工具名称，也不需要先把问题说得很专业。先把真实处境交出来，dbskill 会帮你找到切入点。

## 第一次怎么用

第一次使用，直接输入：

```text
/dbs 新手入门
```

dbskill 会说明你可以提交什么、系统怎样处理、可能得到什么结果。你提交真实任务后，它会从已有信息开始，必要时问你缺少的事实，或请你选择方向。一个 Skill 够用时只用一个；需要几个 Skill 配合时，它会先说明怎么安排、为什么这样安排。

你也可以输入 `/dbs`，然后提交任何真实任务：

```text
我有一个问题还没想清楚：……
这段内容／材料想请你处理：……
我需要判断一个选择：……
这件事一直推进不下去：……
```

例如：

```text
/dbs 我做少儿编程课，已经有 40 个付费学员，但续费低。我不知道是产品问题、定价问题，还是我找错了人。
```

`/dbs` 会读取已有信息，在当前对话中直接开始处理。使用具体 Skill 时会说明名称与分工，并在最终答案保留实际使用项。缺少关键事实时会提问，你无需复制提示词或重复描述背景。只要推荐或需要带到别处的提示词时，也可以直接说明。

## 怎样更新

已经安装 dbskill 后，直接对当前 Agent 说：

```text
更新 dbskill
```

这会调用 `/dbs-update` 同步官方 dbskill。你不需要复制更新命令；它不会更新其他 Skill，也不会修改你的 dbskill 存档。

更新时会自动清理已经下线的旧 Skill：`dbs-hook`、`dbs-xhs-title` 和 `dbs-agent-migration`。只有能确认来自官方的副本才会被清理，原文件备份在 `~/.dbs/retired-skills/`；你自己改过的同名 Skill 会保留。

不通过更新入口时，可以手动清理。Claude Code 插件用户运行：

```bash
claude plugin uninstall dbs-hook@dontbesilent-skills
claude plugin uninstall dbs-xhs-title@dontbesilent-skills
claude plugin uninstall dbs-agent-migration@dontbesilent-skills
```

其他 Agent 在各自的 Skill 目录（例如 `~/.agents/skills/`）中删除这几个文件夹。

## 已经知道要做什么

熟悉 dbskill 后，可以跳过 `/dbs`，直接调用具体 Skill。命令后面直接写材料或问题：

```text
/dbs-diagnosis 我想卖一门给自由职业者的 AI 课，怎样判断这门生意是否成立？
/dbs-title-cover-intro 这是我准备拍的短视频，帮我配套设计标题、封面和开头：……
/dbs-benchmark 我想研究做企业服务内容的账号，帮我找对标。
```

每个 Skill 都会继续追问真正缺少的信息。已经出现在当前对话里的信息，不需要重新回答。

## dbskill 怎样工作

1. 你提交当前的处境、目标、材料和卡点。
2. `/dbs` 判断现在怎样推进：直接回答、问你缺少的事实，或请你决定方向。
3. 需要 Skill 时，`/dbs` 从你要的最终结果倒推，决定用哪几个 Skill、按什么顺序用，并在开始前说明安排和理由。常见的 6 种安排见 [README 的「/dbs 怎样安排 Skill」](../README.md#dbs-怎样安排-skill)。
4. 你补充反馈后，它利用已有信息继续处理；出现反证或方法不匹配时调整，目标完成后结束。

熟悉具体 Skill 后可以直接调用；第一次使用时，直接把任务交给 `/dbs` 即可。

完成任何 Skill 后，可以继续补充事实或直接说明下一步。在 `/dbs` 已经开始处理的对话中，无需反复输入入口命令；单独使用某个 Skill 后，若希望重新选择方法且已安装完整 dbskill，也可以输入 `/dbs`。

## Skill 全目录

以下列出当前正式发布的 35 个业务 Skill。每项均包含适用时机、可直接输入的话和主要产出。

### 入口与商业判断

#### `/dbs`｜技能调度台

**什么时候用：** 你还不确定该从哪里开始，或刚完成一轮 dbskill 工作，想知道下一步。

**你可以这样说：** `/dbs 我有一个线上训练营想法，但不知道该先验证什么。`

**你会得到：** 围绕当前目标的实际处理结果，或推进所需的关键问题；需要时组合能力或比较不同方法，并根据反馈调整。

#### `/dbs-diagnosis`｜诊断商业问题

**什么时候用：** 你要判断一门生意、产品、定价、客户或方向是否成立；也适合对已有业务做系统体检。

**你可以这样说：** `/dbs-diagnosis 我做面向宝妈的收纳咨询，客户总觉得贵。我该降价还是换交付？`

**你会得到：** 问题的消解过程，或一份包含核心判断、风险和处方的商业模式诊断报告。

#### `/dbs-benchmark`｜分析对标

**什么时候用：** 你想找值得长期研究的对象，或已经有候选对象，想判断是否值得学。

**你可以这样说：** `/dbs-benchmark 我想做面向中小老板的短视频，应该研究哪些账号？`

**你会得到：** 经五重过滤后的对标建议，以及具体该研究什么、怎样避免把个人偏好误当判断。

#### `/dbs-theory-grounding`｜挖掘理论依据

**什么时候用：** 你想给自创理论、经验判断、PPT、课程或文案找到可信的理论依据，同时检查原命题是否说过头、来源是否可靠、案例是否硬套名人。

**你可以这样说：** `/dbs-theory-grounding “细节越多，内容越有说服力”这句话成立吗？请找一个可信理论解释我的案例。`

**你会得到：** 命题审查与修正、匹配度最高的理论锚点、来源核实状态、案例重释、适用边界和反例。

#### `/dbs-standard-answer`｜找前人的解法

**什么时候用：** 你面对一个复杂困境，想先知道历史上有哪些结构相似的案例、过去反复有效的解法及其失效条件。

**你可以这样说：** `/dbs-standard-answer 一家靠定制项目赚钱的公司总把产品团队拉回去做交付，历史上有哪些同构案例？`

**你会得到：** 现实问题的结构指纹、成功与失败案例、反例、类比矩阵，以及带适用条件和失效边界的标准答案判断。

#### `/dbs-deconstruct`｜厘清概念含义

**什么时候用：** 一个词在不断影响你的判断，但你说不清它的含义，例如「个人 IP」「赛道」「影响力」「创业」。

**你可以这样说：** `/dbs-deconstruct 个人 IP 到底是什么？`

**你会得到：** 概念在不同场景中的用法、可检验的还原和它与当前问题的关系。

#### `/dbs-goal`｜清晰定义目标

**什么时候用：** 你说「想做个人 IP」「想更有影响力」「想变得更好」，却无法确认要完成什么；也适合检查一项具体任务是否已经说清楚。

**你可以这样说：** `/dbs-goal 我想成为一个有影响力的商业博主。`

**你会得到：** 已有约束的目标卡；任务清楚时直接放行，存在关键缺口时只追问会改变执行或验收的信息。

#### `/dbs-good-question`｜明确定义问题

**什么时候用：** 你有困惑，却无法把它表达成 AI 或他人能真正处理的问题；也适合判断一个问题可自动化到什么程度。

**你可以这样说：** `/dbs-good-question 我总觉得内容不对，但说不出具体哪里不对。`

**你会得到：** 问题的断点、需要补充的事实、可推理的问题说明书，以及 Agent 可解性的判断。

#### `/dbs-jtbd`｜分析顾客任务

**什么时候用：** 你想理解用户需求背后要完成的任务、分析他为什么会换方案，或把产品需求、内容方向和 AI 提示词改成围绕真实进展的表达。

**你可以这样说：** `/dbs-jtbd 用户说想要一门短视频课，帮我判断他在什么情境下想推进什么进展。`

**你会得到：** JTBD 任务陈述、功能／情绪／社会三层任务、切换力量、可观察的选择标准，以及一个最低成本验证动作。

### 内容创作与传播

#### `/dbs-content`｜策划内容方案

**什么时候用：** 选题已经有了，想判断怎样把它做成内容，或想诊断一篇文案、一条视频应该怎样调整。

**你可以这样说：** `/dbs-content 我想讲“普通人别急着做个人 IP”，这个选题怎么做？`

**你会得到：** 推荐形式、五维诊断、具体制作方向、第一步行动和必要的风险提醒。

#### `/dbs-content-risk-check`｜检查内容违规

**什么时候用：** 发布自媒体内容前，想检查敏感词、广告、导流、受限推广、虚假宣传、隐私、视频画面或声明小字。

**你可以这样说：** `/dbs-content-risk-check 这条小红书准备发布，帮我检查哪里可能违规：……`

**你会得到：** 平台机器可能识别的信号、内容本身需要处理的问题、具体位置和最小修改动作；视频里的话容易被断章取义时，还会给出可以直接放在画面上的三行小字。

#### `/dbs-video-navigation`｜视频章节导航

**什么时候用：** 已有本地视频或带时间戳字幕，希望观众知道当前章节、话题或步骤，并看到播放进度。

**直接输入：** `/dbs-video-navigation 为这条视频制作章节导航和动态进度条。`

**你会得到：** 独立导航 MP4、章节时间表、项目快照与摆放说明。仅字幕时需画布、帧率和原片总时长；仅视频时需可用的转写能力。使用 Python、FFmpeg/ffprobe 和适用字体，Agent 会检查转写时间与画面位置。中文教学视频已验证，其他类型尚未系统验证。不会自动剪辑或发布原片。

#### `/dbs-content-value`｜发布前预判效果

**什么时候用：** 发布前或流量低时，希望判断整条内容吸引谁、能否留住人，以及流量和商业价值。

**直接输入：** `/dbs-content-value 这篇稿子会吸引谁，有什么流量和商业价值？`

**你会得到：** 有证据边界的整体判断与改善优先级；逐句共鸣删改、传播机制解释及标题开头生成由各自专用能力承担。

#### `/dbs-title-cover-intro`｜写标题封面与开头

**什么时候用：** 需要生成或修改文字标题、封面文字、短视频开头，或者还没想好这条内容讲给谁听。

**你可以这样说：** `/dbs-title-cover-intro 这是我的文稿，视频还没有拍，帮我配套设计小红书标题、封面和开头。`

**你会得到：** 先是最多 4 个选题，面对的人群从小到大排列，每个附标题示例，并问你能让观众相信你的经历或数字；选定后一屏拿到小红书、B 站、抖音、视频号的标题、封面文字和开头，以及必要的正文修改。

新 Skill 自带参考文件，无需可选知识库。

#### `/dbs-resonate`｜检查文稿共鸣

**什么时候用：** 文稿已经写完，担心没有击中人、完播率低或发出去没有反应。

**你可以这样说：** `/dbs-resonate 这是我的逐字稿，帮我看它有没有戳中真正的受众：……`

**你会得到：** 共鸣强弱判断、情绪与立场的断点、具体删改建议。

#### `/dbs-spread`｜分析传播原因

**什么时候用：** 你想理解一段已有内容为什么能火、击中了什么情绪，或受众接下来还想听什么。

**你可以这样说：** `/dbs-spread 这条内容为什么引发这么多转发？内容是：……`

**你会得到：** 基于 5 个传播学理论的共鸣机制、有效立场、受众情绪和可继续讨论的方向。

#### `/dbs-script-flow`｜检查口播稿流畅度

**什么时候用：** 你有短视频逐字稿，想找出段落衔接、信息密度或口播流畅度造成的划走风险。

**你可以这样说：** `/dbs-script-flow 帮我检查这篇逐字稿哪里会让观众划走：……`

**你会得到：** 分段后的三维检查报告；确认后还可以做保留原文痕迹的标记式改稿。

#### `/dbs-ai-check`｜检查 AI 味

**什么时候用：** 你想检查文案有没有明显的 AI 腔、套路化结构或失真的表达。

**你可以这样说：** `/dbs-ai-check 帮我检查这篇文案有没有 AI 味：……`

**你会得到：** AI 特征检测报告。默认只诊断；你明确说要改时，才进入改写引导。

#### `/dbs-plain-writing`｜平铺直叙写说明

**什么时候用：** 你要写或改产品介绍、功能说明、项目说明、更新说明，希望按事实顺序逐项讲清楚，不要营销腔；也可以只检查措辞歧义，或只改你指定的一处。

**你可以这样说：** `/dbs-plain-writing 平铺直叙地介绍这个工具，把每个功能一条条写清楚：……`

**你会得到：** 直接可用的说明文正文；检查时得到「原句、问题、建议改法」；局部修改只改你点名的部分。

#### `/dbs-wechat-html`｜排版公众号文章

**什么时候用：** 文章已经以 Markdown 写好，需要生成可粘贴到微信公众号后台的排版 HTML。

**你可以这样说：** `/dbs-wechat-html 我的文章.md，做成适合商业分析的风格。`

**你会得到：** 1 个指定或推荐风格、6 个推荐风格，或全部 15 个风格的 HTML 与预览页。

#### `/dbs-content-system`｜内容结构化系统

**什么时候用：** 你已有大量本地文稿、推文、选题、案例或课件，想把它们变成可检索、可重组、可持续生长的内容资产。

**你可以这样说：** `/dbs-content-system 我有 800 篇公众号文章和课程稿，想搭一个内容资产工程。`

**你会得到：** 素材审计、工程结构、内容单元、主题地图与选题装配稿。

#### `/dbs-video-extract`｜短视频信息提取

**什么时候用：** 你有抖音、小红书等短视频链接或完整分享文案，希望取得作品／账号数据、语音文字稿，或两者都要。

**你可以这样说：** `/dbs-video-extract 提取这条短视频的数据和文字稿：……`

**你会得到：** TikHub 可取得的作品／账号数据，以及按作者和标题归档的 Markdown 文字稿。缺少外部服务凭证时，会先用普通语言解释用途，再按完整功能、只看数据或只要文字稿引导购买和安全配置。

### 行动、学习与长期记录

#### `/dbs-action`｜找出拖延原因

**什么时候用：** 你知道该做什么，却总在拖延、准备、反复换方向或回避行动。

**你可以这样说：** `/dbs-action 我知道该每天发视频，但每次写到一半就去研究别人的账号。`

**你会得到：** 对行动阻塞信号的诊断、原因判断和能实际开始的下一步。

#### `/dbs-learning`｜交互式学习

**什么时候用：** 你想系统学习一个主题，希望 AI 根据每一篇后的真实反馈调整下一篇。

**你可以这样说：** `/dbs-learning 带我系统学习定价，每篇都留一道让我反馈的问题。`

**你会得到：** 一份本地学习计划和连续文章；后续输入「继续下一篇」即可基于反馈推进。

#### `/dbs-decision`｜个人决策系统

**什么时候用：** 你需要长期追踪业务、关系、健康、职业、学习或投资中的判断，并通过结果回填逐渐发现规律。

**你可以这样说：** `/dbs-decision 我想长期记录自己的内容业务决策，后面能回看哪些判断有效。`

**你会得到：** 本地决策工程、事件立案、结果回填、状态画像和可升级的规律库。

#### `/dbs-save`｜诊断存档

**什么时候用：** 当前对话已经得出关键结论，想在下次继续，而不从头讲背景。

**你可以这样说：** `/dbs-save` 或 `/dbs-save 训练营定价判断`

**你会得到：** 当前项目下的一份结构化存档，记录结论、否决方向、待验证假设与用户已经确认的下一步。

#### `/dbs-restore`｜接续诊断

**什么时候用：** 你想把上次保存的诊断状态拉回来，继续处理。

**你可以这样说：** `/dbs-restore`、`/dbs-restore list` 或「接着上次」。

**你会得到：** 当前项目最近一次存档及其中已确定的结论、未解决问题和用户已经确认的下一步。

#### `/dbs-report`｜诊断报告

**什么时候用：** 你已积累多次诊断存档，想合并成一份可分享给合伙人、客户或自己复盘的 Markdown 报告。

**你可以这样说：** `/dbs-report` 或 `/dbs-report --since 2026-07-01`

**你会得到：** 按时间整理、去重并分类后的报告文件。

### Agent 工作台

#### `/dbs-knowledge`｜文件夹知识库

**什么时候用：** 你想让 Agent 读懂一个本地文件夹，持续帮你找资料、放资料、调用资料、判断最新版或检查目录是否变乱。

**你可以这样说：** `/dbs-knowledge 帮我把这个文件夹变成知识库，以后我想直接从里面找资料。`

**你会得到：** 一份基于真实目录生成的知识库导航、当前 Agent 的调用入口，以及可以直接复制使用的提问示例。已有成熟目录会保留原结构。

#### `/dbs-install-skill`｜多端 Skill 安装与同步

**什么时候用：** 你已有一个 Skill 或一个 `skills/` 目录，想让 Claude Code、Codex、通用 Agents 与 Grok 都能调用，并保持单一真源。

**你可以这样说：** `/dbs-install-skill skills/dbs-title-cover-intro` 或 `/dbs-install-skill skills`

**你会得到：** 软链 bridge 与 Grok 薄 bridge；也支持查看桥接状态和取消桥接。

#### `/dbs-sync-to-dondon`｜同步给 dondon

**什么时候用：** 你在用 dondon bot，想让它知道你最近在电脑上忙什么，早报和提醒贴着你手上的事。需要 bot 那边已开通这个功能。

**你可以这样说：** `/dbs-sync-to-dondon 把我最近在做的事同步给 dondon`

**你会得到：** 一段 800 字以内的近况和最近用到的文档清单，你确认后推给 bot（没配对时复制给你粘贴）；密钥密码不传，手机号、邮箱等先隐去。也可以开启每天自动同步。

#### `/dbs-human-dispatch`｜人员任务委派与跟进

**适用时机：** 希望 Agent 根据人员资料把任务交给适合的人，写清要求，处理反馈并验收成果。

**你可以这样说：** `/dbs-human-dispatch 把这份产品介绍交给小王，帮我写清交付物和验收标准；没有飞书工具就给我可转发文字。`

**主要产出：** 委派说明、答疑与阻塞处理、按原标准验收和进度汇报。有飞书 CLI 和权限时可读写；自动跟进另需事件订阅、持续运行程序和 Agent 接口。

**使用说明：** [安装、模式与接入](../skills/dbs-human-dispatch/README.md)。

#### `/dbs-skill-maker`｜Skill 制作与改进

**什么时候用：** 你反复遇到同一类问题，想把它做成 Skill；或者已有的 Skill 用起来总出同一类错，想改好它。

**你可以这样说：** `/dbs-skill-maker 我每周都要把客户反馈整理成产品决策，帮我做成一个 Skill。` 或 `/dbs-skill-maker 这个标题 Skill 总是假设观众知道背景，帮我改一下。`

**你会得到：** 先是一份与改动大小相称的方案，你确认后才动文件；然后是新建或修改后的 Skill、用真实任务对比改动前后的结果、本地安装方式。你明确要求分享时，还可以准备 GitHub 仓库和 `npx skills add` 安装命令。

## 常见场景与动态编排

dbskill 不预先规定固定的使用顺序。一个 Skill 够用时直接开始；需要几个 Skill 时，按当前结果决定下一步用什么；同一个问题可能有几种原因时，先找能分辨原因的事实，必要时让几个 Skill 分别分析再比较。结论有分歧时会保留分歧，材料不足时会说明还缺什么。

### 1. 从零开始做内容

```text
/dbs
```

先说清自己的业务、受众与目标。当前问题可能进入内容诊断、开头优化、标题生成或逐字稿检查；由当前结论决定。

### 2. 判断一个生意值不值得做

```text
/dbs-diagnosis
```

先拆清生意和问题。诊断后的结果可能需要寻找现实参照、沉淀长期决策，或先做一项验证动作。

### 3. 从爆款中提炼下一条内容

```text
/dbs-spread
```

先分析已有内容击中的心理与立场。下一步可能需要扩展讨论，也可能可以直接进入内容生产；由分析结论决定。

### 4. 写完一篇内容到发布

```text
/dbs-resonate
```

先检查内容是否真正击中人。结论会指出当前更优先处理共鸣、逻辑衔接、表达问题或发布排版。

### 5. 知道该做却一直做不动

```text
/dbs-action
```

先找行动卡住的具体信号。行动诊断会判断该审计目标、澄清业务问题，还是评估值得承担的摩擦。

### 6. 把本地文件夹变成知识库

```text
/dbs-knowledge
```

指定一个已有资料的文件夹，Agent 会先检查目录和版本关系，再建立可维护的知识库导航。完成后可以直接说「从知识库找一下……」「把这份资料放进知识库」或「检查一下知识库」。

### 7. 建立自己的内容资产与决策记忆

```text
/dbs-content-system
```

先把旧文稿、案例和课程变成结构化资产。后续行动根据素材规模、主题地图和当前业务任务重新判断。

## 使用习惯

- **材料越真实，结果越具体。** 说清楚你卖什么、面对谁、已经试过什么、哪里失败了。
- **不用重复背景。** `/dbs` 和各个 Skill 应先利用当前对话里的信息；只补充真正缺少的事实。
- **跨对话请存档。** 当前聊天记录关闭后，输入 `/dbs-restore` 拉回上次结论。
- **需要重新选择方法时使用 `/dbs`。** 它会按事实和反馈调整；已在入口对话中时，直接补充信息即可。
- **一次只处理一个任务。** 当前结论和你的新反馈会改变下一次编排，因而不预先安排固定长链。
